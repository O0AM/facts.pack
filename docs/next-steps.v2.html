§00
Verdict

Viable format. No-go for feature expansion.

Repair and prove v0.2 before extending it.

All three signed validation paths confirmed four contract defects: invalid canonical examples, contradictory diff row counts, an optional strict trailer, and a validator that does not prove losslessness. They also converged on determinism, resource limits, and encoder parity as the next hardening gate. The roadmap remains useful only in this dependency order.

Go now

Local Gate 0 contract repair, conformance fixtures, governance reconciliation, and private benchmark preparation.

No-go

Normative Wave-1 features, the agent-v5 chain, public benchmark claims, publication, deployment, or promotion of this page to canonical status.

Conditional

Feature work resumes only after byte-exact conformance and private P0.1 evidence clear their gates.

Dependency order, not optimism

Every stage depends on the one before it. The chain, the unique economic moat, comes last: it cannot be built on a contract that two conformant readers resolve differently.

Cross-platform determinism + the benchmark scaffold

Integrity hardening · 2026-06-14 · DONE

Zero-hash seal fallback eliminated; one SHA-256 everywhere

  • ✓Zero-hash fallback removed. When crypto.subtle was unavailable (a non-secure context) the web emitter sealed sha256=000000000000 — an unverifiable trailer. sealPack now uses a synchronous pure-JS SHA-256 with no crypto.subtle dependency, so it always seals a real digest. Where: docs/index.html (and the archived v1.editorial). Verified by grounding ZH-a/ZH-b + security INT-3: with crypto.subtle forced to throw, the trailer is still a real, decoder-accepted digest.
  • ✓Dependency-free reference codec. The codec's node:crypto import was replaced by the same pure-JS sha256hex (FIPS 180-4); the vendored bundle now carries zero node:crypto imports. Where: factstack sha256.ts → test/factspack.bundle.mjs. Verified: upstream vitest 175 + a 2227-case fuzz of the shipped web hash vs node:crypto (every padding boundary, unicode, multi-block) — 0 mismatches.
  • ✓Adversarial pass. A 4-lens review (correctness · test-soundness · remnant-sweep · overclaim) cleared the change; its real catches were applied — the now-sync sealPack callers dropped their stale await, parity wording was scoped to the digest, and the round-trip proof's body slice was made length-exact.
  • ✓Digest parity. Browser emitter, reference codec, and node:crypto compute the same trailer hash VALUE. (Full encoder BODY parity landed in the next phase.)
Encoder unification · 2026-06-14 · DONE

Browser converter and reference codec are now ONE encoder (byte parity)

  • ✓One encoder, not two. The converter's bespoke emitter (its own interning, escaping, sealing) was retired. It now calls the reference codec's encodeAuto — an automatic-economic interning producer profile (a planner over encode()) — esbuild-inlined into the single self-contained page. So the browser and the reference producer run the SAME encoder and agree on the wire (body AND digest). Was: two independent emitters that could drift (Finding 07).
  • ✓Byte parity, proven + guarded. test/parity.mjs asserts the inlined encoder === the reference codec byte-for-byte (full body, not just the digest), and the converter's real output strict-decodes with its legend matching the on-wire schema. conformance adds PARITY-byte, INLINE-DRIFT, and BUNDLE-DRIFT so neither vendored copy of the encoder can silently diverge from source.
  • ✓Adversarial pass + regressions fixed. A 5-lens review (encodeAuto correctness · adapter fidelity · parity soundness · overclaim · regression) found and closed real gaps: a newline-in-column-name throw, a legend/schema casing mismatch, CRLF handling, and a missing bundle drift guard — each now covered by a test. Placement note: the codec repo's tooling prunes new source files, so the encodeAuto profile is currently vendored in facts-pack over the codec's tracked encode(); byte-parity holds either way.
Full-pack determinism · 2026-06-14 · DONE

Gate 1 closed: the same input yields a byte-identical pack

  • ✓Canonical-producer profile. The converter no longer stamps a wall-clock into the header. In canonical mode encodeAuto pins snapshotId to a content digest of the data (a 12-hex SHA-256, itself a valid cache key) and drops the generated field, so two runs of the same paste emit a byte-identical pack, header included. Where: test/_encode-auto.ts, docs/index.html, spec §4.6. Verified by conformance DET-3 + DET-3-id.
  • ✓Gate 1 complete. Determinism (DET-1/2/3), resource ceilings, and encoder byte-parity all hold, so the determinism + hardening gate is done. What remains is Gate 2's owner-gated benchmark, which is not a conformance property.

§02
Findings

What the review found

Eight entries. Four contract defects were confirmed independently by Claude, Antigravity, and Codex. Four integration and hardening gaps shape Gate 1. Explanations remain collapsed until opened.

Filter 8 shown
01 Canonical examples are not valid wire bytes Criticalverified · CC + AG + OC+

FACTSPACK.md:81 mandates the field separator be a tab (0x09), but the worked examples at :241 and :272 contain zero tab bytes; every separator is a space. The decoder splits strictly on tabs, so a reader who copies the spec's own "lossless round-trip" example produces a row with the wrong cell count and is rejected.

Resolution Generate the docs from byte-exact fixtures, render a visible tab marker alongside, and decode plus re-encode every normative example in CI.
02 The diff row-count rule contradicts itself Criticalverified · bundle.mjs:112/114/431+

A diff sets the header row-count to 0 ("patch only") but the spec demands the trailer equal the header count when it is not -. Since 0 is not -, the rule requires the trailer to equal zero while the diff carries real operations. The shipped decoder never compares the two, so the integrity guarantee is absent precisely where the chain depends on it.

Resolution Define three distinct quantities: master header equals the baseline count; the diff header is a zero sentinel bound to kind=diff; the trailer counts physical operations. Require equality for masters only. Block the chain until this lands.
03 Strict v0.2 integrity is optional in the decoder Criticalverified · decoder+

A pack with no trailer returns success. The decoder cannot distinguish a legitimate pre-v0.2 pack from a truncated v0.2 one, and it never validates the header row-count against anything. The spec says a v0.2 consumer must verify the trailer is present; the reference decoder does not.

Resolution Split behaviour into explicit strict and legacy profiles. Strict requires the trailer, header validation, operation legality for the kind, duplicate rejection, and resource limits.
04 The validator proves acceptance, not losslessness Highverified · validate.mjs:21+

The test oracle maps a literal - to the Unicode minus sign, then counts the affected cases as passing under a lossless label. It normalizes away the exact loss it should detect. Its object flattening descends only one level. "Fifteen of fifteen pass" is useful smoke coverage; it is not a round-trip proof.

Resolution An independent exact round-trip oracle that preserves every supported value and shape, and rejects genuinely ambiguous input with a precise error rather than coercing it green.
05 Byte-determinism was assumed, never tested — RESOLVED (now proven by DET-1/2/3) High · RESOLVEDintegration · canonicalization is normative + tested+

Was: float formatting, dictionary-key order, and Windows-vs-POSIX path separators were unpinned with zero conformance test, so the cache moat's "same input, same bytes" was unverified. Now: canonicalization is normative (spec §4.6 — POSIX paths, pinned numbers, sorted walks) and the canonical-producer profile pins the header to a content digest, so the whole pack is byte-identical for identical input.

Resolved conformance DET-1 (in-process), DET-2 (Windows vs POSIX paths emit identical bytes), and DET-3 + DET-3-id (the shipped converter emits a byte-identical full pack across runs) all pass. See the §Δ "Full-pack determinism" fixes phase.
06 The decoder has no resource ceilings Highintegration · source-verified gap+

The local decoder has no configurable limits on bytes, lines, rows, columns, tables, or dictionary entries. That absence is source-verified. Earlier reports assert exposure through a live Workers path, but that deployment topology is not reproducible from this checkout and is therefore not presented here as a local fact.

Resolution Configurable caps on bytes, lines, rows, columns, tables, and dictionary entries; add resource-exhaustion cases to the corpus.
07 Browser and reference encoders had no parity test — RESOLVED (now one encoder) High · RESOLVEDintegration · unified on the reference codec+

Was: the browser emitter and the reference encoder were independent code and could drift while validation (decode-only) stayed green. Now: the converter emits via the reference codec's encodeAuto, esbuild-inlined into the page, so the two producers are literally one encoder.

Resolved test/parity.mjs asserts the inlined encoder === the reference codec byte-for-byte (full body); conformance adds PARITY-byte + INLINE-DRIFT + BUNDLE-DRIFT drift guards. See the §Δ "Encoder unification" fixes phase.
08 The published test count is stale Mediumintegration · 143 claimed, 106 found+

FACTSPACK.md claims 143 tests. The current external factstack suite contains 106 test cases across four test files. The stale number is a credibility defect even if every present test passes.

Resolution Generate the count from the test runner or avoid a hard-coded number in normative documentation.

§04
Roadmap

The path, in dependency order

Not four waves of features. A correctness gate, then a measurement gate, then features admitted one proven delta at a time.

Gate 0 · blocking · now

Repair the v0.2 contract before any v0.3 feature

  • 1Valid canonical examples. Regenerate the spec's worked examples from byte-exact tab fixtures with a visible tab marker.
  • 2Fix diff and master count semantics. Separate the quantities; enforce header-trailer equality for masters only.
  • 3Strict and legacy decoder profiles. Strict v0.2 requires the trailer, validates counts, rejects duplicate or illegal operations, and leaves legacy acceptance explicit.
  • 4Independent exact oracle. Preserve literal values and supported nesting without normalization, then reject ambiguity precisely.
  • 5Correct the test inventory. Replace the stale 143-test claim with a generated count or no count.

Gate 0 changes are local contract repair. They still follow the project process: research, consensus amendment, roadmap encoding, then any spec edit.

Gate 1 · conformance + hardening

Prove deterministic, bounded, equivalent implementations

  • 1Cross-platform byte determinism. Pin number formatting, dictionary order, path normalization, legend wording, and tie-breaks.
  • 2Resource ceilings. Bound bytes, lines, rows, columns, tables, dictionaries, and deferred references with adversarial fixtures.
  • ✓Encoder parity — DONE. The browser and reference encoders emit identical canonical bytes for the same input: the converter now runs the inlined reference codec (one encoder). Proven by parity.mjs, guarded by INLINE-DRIFT + BUNDLE-DRIFT.

Gate 1 is complete only when the same fixtures pass the independent strict decoder on every supported platform.

Gate 2 · P0.1 · private evidence

Measure the core claim before publishing it

  • 1Reproducible accuracy and token benchmark. Pack versus JSON, CSV, Markdown-KV, and TOON on a real code map, with pinned models, fixed temperature, checked-in fixtures, and pre-registered confidence intervals.
  • 2Private first. Results remain local until the owner explicitly approves publication. No benchmark number enters a public surface before the harness can reproduce it.
Owner constraint · licensing

The license remains unchanged

  • ✓Settled: AGPL-3.0 plus commercial dual licensing for all code, codec included.
  • ?Owner-only open question: whether spec text and conformance fixtures receive a permissive documentation or data license. This review records the question and makes no recommendation.
  • ×Strike: any claim that a process boundary determines copyleft scope. Describe architecture; leave legal conclusions to qualified counsel.
Gate 3 · additive, wire-compatible

Emit what is computed, once it earns its place

  • +Communities table with a deterministic heuristic label (summary column off the hashed wire).
  • +Datatypes in ; comment lines, scoped to storage-form specials.
  • +Incident edge ordering codified as a canonicalization rule.
  • +Capability line and canonicalization section, both wire-compatible.

Impact unmeasured. Each item must show a measured delta on the P0.1 code-map benchmark, or it does not ship.

Gate 4 · breaking, agent-v5 + chain

Stable identity, then the chain

  • ·Position-free monikers. Lite heuristic monikers are hints only; they may never key a delete or replace.
  • ·Collision-free value representation. Resolve empty, missing, and literal sentinel values only in a new wire major.
  • ·The master and diff chain. Build only after identity is stable, with measured coalescing policy and an explicit concurrency model for multi-agent repositories.

Cache economics are the real moat, and unproven: a token floor and a short TTL mean the win can be negative for small or intermittent packs.

Wave 3 · ecosystem

Ports, conformance, editors

  • ·Spec-repo split with language-agnostic conformance fixtures; first-party Python port and CLI (decode and validate first).
  • ·Escaping is the real injection defence (shipped). XML is organization, not a shield. Authenticity, if added, is an out-of-band signature attesting origin only.
§05
Consensus

What the next consensus amendment must say

R1 through R7 remain useful, but the final validations add blocking evidence. Reconciliation belongs in the consensus document before any roadmap or spec change.

R1

Datatypes are an experiment

Additive ; types only. Decoded values remain v0.2-equivalent, and admission requires a measured delta.

R2

No settled chain threshold

Separate correctness limits from performance policy. Derive coalescing from a measured chain-depth curve.

R3

Do not overload an empty sentinel

Use a derived projection now. Reserve an unambiguous escape only for a new wire major.

R4

Lite monikers are hints

Never use probabilistic identity as a destructive mutation key. Ambiguity resolves to delete plus add.

R5

Record evidence provenance

Distinguish source-verified, author-reported, hypothesis, unknown, and rejected claims on every surface.

R6

License unchanged

AGPL plus commercial remains settled. Record the spec and fixture license as owner-only open, with no recommendation.

R7

Canonicalization before capabilities

Make determinism normative, caps enforceable, and the adversarial corpus broader. Capability lines remain descriptive.

Governance order: amend consensus with attribution, encode the result in planning/ROADMAP-v0.3.md, and only then consider a change to FACTSPACK.md.
