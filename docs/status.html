What is built

Each line ships behind a green suite. The + is the format's own "added" marker.

+
Strict-default decoder + legacy profile
decode() is strict by default (trailer required, counts and kinds enforced, resource ceilings); decodeLegacy() preserves pre-v0.2 tolerance behind an opt-in.
verified by grounding 03a-03c, security
+
Master / diff count semantics
Three distinct quantities: master header equals trailer, the diff header is a 0 sentinel bound to kind=diff, the trailer counts physical operations.
verified by grounding 02a-02e, decode.test.ts
+
Decoder resource ceilings
Configurable caps on bytes, lines, rows, columns, tables, and dictionary entries, enforced mid-parse so a hostile pack fails fast.
verified by grounding 06a-06d, security
+
Byte-exact canonical examples + fixtures
The spec's worked examples are generated from real-tab fixtures that decode under strict and re-encode byte for byte, rendered with a visible tab marker.
verified by grounding 01a-01e, conformance
+
Independent exact round-trip oracle
A separate oracle with no shared normalization asserts decode(encode(x)) equals x, catching losses the old validator was blind to.
verified by oracle.mjs 7/7, grounding 04c/04d
+
Cross-platform canonicalization (v0.3)
POSIX path normalization, pinned number formatting, sorted walks: the same code map emits identical body bytes on Windows and POSIX.
verified by conformance DET-2, canonicalize.test.ts
+
Dependency-free pure-JS SHA-256
node:crypto replaced by an isomorphic SHA-256; the digest is identical in Node and the browser, fuzzed over every padding boundary, unicode, and multi-block input.
verified by 2227-case fuzz vs node:crypto (0 mismatches)
+
Zero-hash seal fallback eliminated
The web emitter used to seal sha256=000000000000 in a non-secure context; it now always seals a real, verifiable digest with no crypto.subtle dependency.
verified by grounding ZH-a/ZH-b, security INT-3
+
Encoder unification (one encoder)
The browser converter emits via the inlined reference codec's encodeAuto producer profile, so browser and reference output are byte-identical and guarded against drift from source.
verified by parity.mjs (22), INLINE-DRIFT, BUNDLE-DRIFT
+
Adapter robustness, adversarially reviewed
Legend tokens match the on-wire schema, CRLF is normalized, colliding column names are de-duplicated (no silent field merge), and the codec's throw surfaces a visible error.
verified by COLDUP-a/b/c, E2E-legend, LI1-LI4

Gate 1's last item, now closed. The converter pins the header's snapshotId to a content digest and drops the wall-clock, so two runs of the same input emit a byte-identical pack, header included. Same data yields the same id; different data yields a different id.

05

Kept honest

Caveats live at the same hierarchy as the claims they qualify.

// placement

The encodeAuto profile logically belongs in the canonical codec, but that repo's tooling prunes new source files unreachable from its managed index. So it is vendored in facts-pack over the codec's tracked encode(). Byte-parity holds regardless of where it lives.

// no fabricated numbers

Every figure here comes from a real run: the token study is real BPE over real repos, the accuracy pilot is a real Sonnet 4.6 reader, the chain savings are measured bytes. The full multi-model benchmark stays unrun rather than guessed until keys exist. The format's pitch is rigor, so its scoreboard cannot cheat.

// grounded in bytes

Nothing here is trusted because a document or this agent asserted it. Each line maps to a suite that runs against real fixtures and live decoder behavior, or it is flagged as unverifiable.

// wire-compatible

Every change shipped to date is wire-compatible: a v0.1 or v0.2 pack still decodes. The breaking changes are quarantined behind Gate 4 (agent-v5), frozen until the benchmark earns them.
