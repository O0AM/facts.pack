FactsPack · an open standard · file extension .pack

Structured data your AI agent can afford to read.

FactsPack is a line-oriented text format that streams tabular data to LLM agents at roughly one-fifth the token cost of JSON, while staying human-readable, append-friendly, self-describing, and tamper-evident.

Invented & authored by Aditya Mishra · Open source under AGPL-3.0

Standard v0.2 · Implemented

Abstract

Seven line types form the whole grammar. Column names appear once; heavy repeated strings are interned in a dictionary; updates ship as appended diffs. Measured on the author's codebase-map payloads: 5,000 symbols cost 150k tokens as JSON and 28k as PACK (−81%); 10,000 import edges, −91%. Calibration against third-party benchmarks appears in §7. An 8-line preamble teaches any model to read it.

Prefer it explained with mammoths and berries? Read the ELI5 caveman explainer.

1

Why it exists

When an agent calls a tool that returns 5,000 records, JSON repeats every key ("id", "kind", "name", "file") and every quoted file path on every single record. Context windows are paid by the token; that repetition is pure cost.

Three moves get it there:

  1. schema onceColumn names appear a single time, as in CSV. Rows are positional.
  2. strings internedHeavy repeated values (file paths, rule ids) appear exactly once in a dictionary; rows reference them as F1, F2.
  3. 1-char prefixesNo braces, quotes, or per-record delimiters. The first byte of each line is the syntax.
2

Anatomy: seven line types

A .pack is a stream of UTF-8 lines. The first character routes each one. Fields are separated by a real tab; \t \n \\ are the only escapes. There is no quoting layer.

PrefixRoleExample
#Header: producer, schema-version, commit, row count (v0.2 adds seq, parent hash, master|diff, timestamp)# factstack/0.3.10 agent-v4 88e9a1b 5000
;Meta (v0.2): in-band legend, ; hot: hints, and the final integrity trailer; end rows=5000 tables=12 sha256=7af2c59b6d8a
@Dictionary: intern a repeated string under a short key@ F1=src/auth.ts
&Schema: table name + columns; UPPERCASE columns are interned (cells hold dictionary keys)& symbols id k n F l
-Row: tab-separated cells, positional per the active schema- 1 fn login F1 42

Row 1 reads: symbol 1, kind fn, name login, file src/auth.ts (expanded from F1; the F column is uppercase, so its cells are dictionary keys), line 42. The gap widens with scale: JSON's overhead is per-record, PACK's is one-time.

Multi-table streams and incremental updates

One pack can carry several tables, since each & line switches the active schema: symbols, imports, and findings travel in a single response. And a follow-up payload ships only what changed:

Exhibit C · refresh.packrow count 0 = patch only
# facts/0.1 symbols-v1 88e9a1b 0
@ F1=src/auth.ts
& symbols  id  k   n      F   l
+ 6   fn  reset  F1  70
x 3

v0.2 formalizes this into hash-linked chains: an immutable master.<seq>.pack plus per-commit .pack-diff files, each naming its parent's SHA-256. A session pins its master and appends diffs, so the LLM provider's prompt cache keeps serving the large prefix at cached-read prices (roughly a tenth of fresh-input cost on typical providers) instead of being invalidated by every refresh.

The laboratory: try it on your own bytes

Two instruments. First, a scaling model: drag the sliders and watch the gap between encodings widen as data grows and file paths repeat. Second, a converter: paste real data, leave with a real .pack and the prompt that teaches any AI coding agent to read it. Everything runs in your browser; nothing is uploaded.

Paste bytes, leave with a pack

Detection is automatic. Structured data (JSON, NDJSON, CSV, TSV, Markdown tables) converts losslessly into tabular PACK. Source files (JavaScript, TypeScript, Python, Java, Go, Rust, C, Ruby, PHP, HTML, CSS, Markdown) become a map-pack of declarations and imports, which is how the format is used on real codebases: the agent orients from the map and opens files only when needed. Paste several files at once by separating them with a line like // file: src/app.js.

5

Built for a consumer that hallucinates

Classic formats assume a parser that either succeeds or throws. FactsPack assumes a language model: a reader that guesses when underinformed, trusts what it reads, and acts on stale facts confidently. The v0.2 trust laws answer each failure mode.

  1. In-band legendEvery pack documents its own tables, columns, and units in plain language (; lines). Self-description beats compression. A cold model needs no external spec.
  2. Integrity trailerThe final line, ; end rows=… tables=… sha256=…, makes truncation and tampering detectable. Missing or mismatched? Reject; never best-effort parse.
  3. Injection armorCell values and quoted code are data, never instructions. Source carried inside a pack cannot address the reading agent.
  4. Freshness contractThe header carries the git commit it was built from. Differs from HEAD? The pack is stale: regenerate before trusting facts.
  5. DeterminismIdentical input produces a byte-identical pack. "Skip when unchanged" becomes decidable, and cache prefixes stay stable.
  6. The agent ritualThe tool types, the agent signs. Packs are emitted by tools and validated by decoders; agents annotate. They never hand-write facts.

One standard, two profiles

Tabular map-pack

The grammar above. Used by factstack for its codebase map (agent.pack, wire tag agent-v4): 13 tables, led by a ranked top head, then files, imports, routes, risks, envs, declarations, symbols, calls, node metrics, rationale, entities, and entity edges.

Prose fix-pack

The facts+ audit work-order: severity-ordered issues, each self-contained (id, severity, problem, why it matters, standards, exact file:line:col location with a content hash, quoted code with the cited line marked <<<, and the fix). Same trust laws, prose body. Its saving is eliminated tool calls, not compression.

How it compares

Every ingredient (positional rows, sigil prefixes, dictionary encoding, delta rows, hash chains, self-description) exists somewhere in prior art. The invention is the combination, tuned for one new consumer: an LLM reading data inside a paid, cache-priced context window.

FormatSharesFactsPack difference
TOON (the dominant LLM format, ~16k★)Same headline goal; schema-once positional rows; declared row counts as a completeness guardrailTOON is a lossless JSON replacement. PACK adds the envelope it lacks: dictionary interning, multi-table streams, diffs, hash chains, integrity trailer, cold-read legend, trust rules.
TRON · CTON · JTON · TERSE (2025–26 siblings)Schema-once positional rows for LLM token savingsAll optimize the row layer; none has interning, multi-table framing, hash-chained diffs, an integrity trailer, or an injection rule. PACK's distinct value is the envelope.
CSV / TSVSchema-once positional rows; TSV rows are PACK's row layerInterning, multi-table, typed prefixes, increments, integrity trailer, and no quoting layer to get wrong.
JSON Lines / NDJSONLine-oriented, streamableJSONL repeats every key per record, the exact overhead PACK removes.
ARFF (Weka)Declared schema + positional rows; the closest classic "schema once" ancestorSingle table, no interning, no increments, no integrity layer; built for ML datasets, not agent wire traffic.
VCF / SAM / GFF3Closest structural ancestors: sigil-prefixed headers + tab-separated rows; SAM's @ is the nearest one-char-prefix precedentDomain-fixed genomic schemas; reference-by-id only; integrity lives in external indexes, never an in-band trailer; no LLM legend or trust rules.
RDF Turtle @prefix / JSON-LD @contextThe cleanest text precedent for @-aliasing repeated strings, and for the @ sigil itselfPACK generalizes it to one flat dictionary shared across every table in the stream, read directly by the model.
Apache AvroIn-band writer schema + formal schema evolutionAvro is binary; PACK is text and versions via the header with explicit major/minor rules.
Parquet / ArrowDictionary encoding, the same compression ideaBinary and columnar: needs a library between data and model. PACK applies the idea in a form an LLM reads directly.
Protobuf / ASN.1 / CBOR / MessagePackSchema-once positional or compact serializationBinary is token-hostile: base64 into a prompt costs more than JSON, and a model cannot read it cold.
JSON Patch / unified diff · git · Delta Lake / IcebergIncremental updates and hash-linked append-only historyPACK's +/x are schema-aware row ops carrying provenance; its linear master/diff chain is purpose-built for LLM prompt-cache stability.
Markdown tables · llms.txt · RepomixLLM-friendly rendering / "prepare content for LLMs"Content and packaging conventions with no machine contract; PACK is a data format with a grammar, decoder, and validation.
An honest word on the numbers. The −81% and −91% figures are the author's measurements on codebase-map payloads, where file paths repeat thousands of times: the case interning is built for. Independent benchmarks of schema-once LLM formats land lower (roughly 28–40% vs JSON); PACK reaches the high end only because three savings stack: dropping JSON's per-row keys, interning heavy repeated strings, and shipping deltas instead of whole tables. Believable for this workload, weaker without repetition. Measure on your own payloads.

Not to be confused with

The name "FactsPack" is clear (unclaimed on npm, PyPI, crates.io, and GitHub as of June 2026), but the .pack extension is crowded, so the format is identified by its # header line, never the extension.

Git packfiles (.git/objects/pack/*.pack), the dominant association

Git's internal binary object storage uses the same extension; zero relation. A FactsPack always begins with a # header line and is plain UTF-8 text; a git packfile begins with the binary magic PACK. (A web search for "pack format" returns git's docs first.)

Total War PackFile · Java Pack200 · libGDX atlas · CMSIS-Pack · Minecraft "pack format"

Binary game-asset archives, a dead JAR compressor, texture atlases, embedded-toolchain zip archives, and a Minecraft version integer (its packs are actually .zip/.mcpack). All unrelated; the #-header sniff test distinguishes them. A secondary extension like .fpack is a reasonable escape hatch if tooling ever misclassifies .pack as binary.

8

Use it in five minutes

  • Reading: paste the 8-line preamble from FACTSPACK_PROMPT.md into any LLM conversation, or just hand a v0.2 pack over; its in-band legend covers a cold reader.
  • Writing: emit a # header, a ; legend, @ entries for repeated strings, one & per table, - rows, and the ; end trailer. Intern only columns whose values repeat.
  • Validating: the reference encoder/decoder (TypeScript, zero runtime deps, 143 tests) ships in factstack's packages/factspack; the decoder is strict. Reject, never best-effort.
  • Don't: use it for storage, browsers, small varied records, trees, prose, nested objects in cells, or binary blobs. JSON, plaintext, and Markdown keep those jobs.
